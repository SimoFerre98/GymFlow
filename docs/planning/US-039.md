# US-039: Sospendere il deploy web finché il target non viene recuperato

**Epica:** EP-001 | **Punti:** 1 | **Branch:** `feature/US-039-suspend-web-deploy`
**Piano redatto:** 2026-08-06

## Contesto

`.github/workflows/deploy_web.yml` si attiva su ogni push a `main` e `master` (righe 2-6) ed esegue `flutter build web --release` (riga 19) prima di pubblicare su Firebase Hosting.

Quel comando **fallisce sempre**: il codice generato da Isar in `lib/src/models/local/local_workout_session.g.dart` contiene interi a 64 bit non rappresentabili in JavaScript (verificato in questa sessione, cinque errori distinti). La pipeline è quindi rossa a ogni merge dal commit che ha introdotto Isar.

Con il target Web accantonato in EP-008, il fallimento non è più un difetto da correggere a breve: è rumore che nasconde eventuali fallimenti reali.

Note sul repository:
- Non esiste il branch `master`: il trigger su quel ramo è già inerte.
- È l'unico workflow presente in `.github/workflows/`.
- US-029 introdurrà un workflow di verifica su pull request: sarà quello il segnale di CI utile nel frattempo.

## Obiettivo

Impedire l'esecuzione automatica del deploy web, conservando il workflow e la possibilità di lanciarlo a mano.

## Approccio

Sostituire il trigger `on: push` con `on: workflow_dispatch`, aggiungendo in testa al file un commento che spiega la sospensione, la rimanda a EP-008 e indica come annullarla.

`workflow_dispatch` è la scelta giusta perché soddisfa insieme i due criteri in tensione della storia: nessuna esecuzione automatica, ma workflow ancora avviabile dalla scheda Actions. La reversibilità è massima: si ripristinano le righe del trigger e si rimuove il commento.

Il blocco `jobs:` non viene toccato. Sistemarlo — versione di Flutter fissata, deploy condizionato al build — è compito di US-004, alla ripresa di EP-008.

### Alternative scartate

| Alternativa | Perché no |
|---|---|
| Eliminare il file | Perde configurazione, segreti referenziati e cronologia. US-004 dovrebbe riscriverlo da zero |
| Rinominare in `.yml.disabled` | Ottiene lo stesso risultato ma rende il workflow non avviabile a mano, violando il secondo criterio |
| `if: false` sul job | L'esecuzione parte comunque e appare nella lista come "skipped": rumore ridotto, non eliminato |
| `continue-on-error: true` | Il workflow gira, spreca minuti di CI e riporta successo su un build fallito: peggio del problema |
| Correggere subito il build web | È US-003, 5 punti, esplicitamente accantonata per decisione di prodotto |

## Piano di test

| Criterio di accettazione | Come lo verifico |
|---|---|
| Non più eseguito automaticamente sui push a `main` | Il file non contiene più un trigger `push`; controllo testuale sul YAML |
| Resta nel repository e avviabile manualmente | Il file esiste ed è presente `workflow_dispatch` |
| Commento che spiega la sospensione e rimanda a EP-008 | Lettura del file: il commento cita EP-008 e le istruzioni di ripristino |
| Dopo un push su `main`, nessuna esecuzione fallita | Verifica su GitHub dopo il merge. **Osservabile solo a valle**: prima di allora la prova disponibile è l'assenza del trigger nel file |
| Sospensione reversibile con la sola riattivazione del trigger | Il `diff` rispetto a `main` è limitato al blocco `on:` e al commento; nessuna modifica al job |

Il YAML si valida con il parser di Python, già disponibile:

```bash
python -c "import yaml,io;d=yaml.safe_load(io.open('.github/workflows/deploy_web.yml',encoding='utf-8'));print(d.get(True) or d.get('on'))"
```

> Nota: in YAML 1.1 la chiave `on` viene interpretata come booleano `True`, da cui il doppio accesso.

## Rischi

| Rischio | Come me ne accorgo | Mitigazione |
|---|---|---|
| YAML malformato: workflow ignorato senza avviso | Validazione con parser prima del commit | Passo 5 obbligatorio |
| Il deploy resta sospeso e ce ne si dimentica | Nessun segnale automatico | Commento nel file, nota in EP-008, criterio esplicito in US-004 |

| Perdita del segnale di CI sui merge | Nessun controllo automatico fino a US-029 | US-029 è nella stessa fase dell'ordine di esecuzione |
