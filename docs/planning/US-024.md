# US-024: Sostituire le API deprecate di colore e tema

**Epica:** EP-005 | **Punti:** 3 | **Branch:** `feature/US-024-replace-deprecated-apis`
**Piano redatto:** 2026-08-06

## Contesto

`flutter analyze` riporta 172 avvisi, di cui la grande maggioranza sono `deprecated_member_use` su API di colore e tema. Cinque famiglie distinte:

| API deprecata | Occorrenze | Sostituto |
|---|---|---|
| `Color.withOpacity(x)` | 95, in 21 file | `Color.withValues(alpha: x)` |
| `ColorScheme.background` / `onBackground` | 4, in `app_theme.dart` | `surface` / `onSurface` |
| `MaterialStateProperty` | 2, in `app_theme.dart` | `WidgetStateProperty` |
| `Color.value` | 3 (`theme_provider.dart`, `settings_screen.dart`) | `Color.toARGB32()` |
| `Switch.activeColor` | 1, `settings_screen.dart:421` | `activeThumbColor` |

`withOpacity` è deprecata per perdita di precisione: converte a un canale alpha intero a 8 bit, mentre `withValues` mantiene la rappresentazione in virgola mobile.

Due accertamenti fatti prima di pianificare:

- **`background` e `onBackground` non hanno consumatori.** Ricerca su tutto `lib/` fuori da `app_theme.dart`: zero occorrenze. Rimuoverli dal `ColorScheme` non rompe nulla, tanto più che `surface` e `onSurface` sono già valorizzati con gli stessi colori.
- **`activeColor` in `main_screen.dart:48` non è deprecato**: appartiene a `GNav` del package `google_nav_bar`, non a `Switch`. Non va toccato. L'unico `activeColor` da sostituire è quello di `settings_screen.dart:421`, su uno `SwitchListTile`.

Questa storia è prerequisito di US-033: costruire i token Material 3 Expressive su API in via di rimozione significherebbe rifare il lavoro al primo aggiornamento di Flutter.

## Obiettivo

Azzerare gli avvisi `deprecated_member_use` su colori e tema, senza alcun cambiamento visivo.

## Approccio

Sostituzione meccanica, famiglia per famiglia, con verifica automatica del conteggio prima e dopo.

Per `withOpacity` la trasformazione è puramente sintattica: `X.withOpacity(E)` → `X.withValues(alpha: E)`, dove `E` è un'espressione qualsiasi. Uno script con parsing bilanciato delle parentesi copre i casi in cui `E` contiene a sua volta chiamate. Verifica: il numero di `withValues(alpha:` dopo deve essere pari al numero di `withOpacity(` prima, e `withOpacity` deve sparire.

Per `Color.value` nel confronto di `settings_screen.dart` si usa `toARGB32()` su entrambi i lati, mantenendo la semantica di confronto per valore ARGB.

### Alternative scartate

| Alternativa | Perché no |
|---|---|
| `dart fix --apply` | Non copre `withOpacity` → `withValues` (nessun fix automatico registrato) e agirebbe indiscriminatamente su tutto il progetto, comprese correzioni fuori scope |
| Sostituzione a mano una per una | 95 occorrenze: alto rischio di errore umano e nessun vantaggio, la trasformazione è deterministica |
| Sostituire `withOpacity` con `Color.fromRGBO` | Cambia la forma del codice senza motivo e perde la leggibilità dell'intento |
| Confrontare i colori con `==` invece di `toARGB32()` | `Color ==` confronta anche lo spazio colore: più fragile del confronto esplicito sul valore ARGB |

## File toccati

| File | Intervento |
|---|---|
| 21 file in `lib/src/ui/` e `lib/src/core/theme/` | `withOpacity` → `withValues(alpha:)` |
| `lib/src/core/theme/app_theme.dart` | Rimozione di `background`/`onBackground`; `MaterialStateProperty` → `WidgetStateProperty` |
| `lib/src/core/providers/theme_provider.dart` | `color.value` → `color.toARGB32()` |
| `lib/src/ui/screens/settings_screen.dart` | Confronto colori con `toARGB32()`; `activeColor` → `activeThumbColor` |
| `docs/BACKLOG.md` | Stato e criteri |

## Passi

1. Conteggio di partenza per ciascuna famiglia.
2. Sostituzione di `withOpacity` con parsing bilanciato.
3. Sostituzioni puntuali delle altre quattro famiglie.
4. Conteggio finale: zero occorrenze residue.
5. `flutter analyze`: nessun avviso `deprecated_member_use` sulle API trattate.
6. Esecuzione su emulatore e confronto visivo.

## Rischi

| Rischio | Come me ne accorgo | Mitigazione |
|---|---|---|
| Parsing errato di una `withOpacity` annidata → codice non compilabile | `flutter analyze` riporterebbe un errore di sintassi | Parsing bilanciato, non regex ingenua; conteggio di controllo |
| Rimozione di `background` con un consumatore non rilevato | Errore di compilazione | Ricerca preventiva già fatta: zero consumatori |
| Differenza cromatica impercettibile all'analisi ma visibile a schermo | Confronto su emulatore | `withValues(alpha:)` è più preciso, non meno: nessuna perdita attesa |
